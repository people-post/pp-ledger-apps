| Admin (ad6) | Done | `pp-ledger-admin`: mint (within the cap per epoch, fee included; a cap of 0 mints nothing), config update (every setting an update may change, in force beside the new value; refused while one is pending, while the admin set is frozen, or by pp-ledger's liveness and block-size rules), admin-set rotation (chosen from the set in force, others' key cards and the vault's admin keys; at least 3, 2 to sign), the next beacon certificate (from the beacon's key card; no cutover). Builders in `apps_net` (`AdminOperations`, unit-tested); reviews in role apps show what a config update or certificate changes against the chain now (`Session::compare`; the Signer, offline, shows the operation alone). | Registrar (ad7) | Done | `pp-ledger-registrar`: an issued account (a number in 2^20 … 2^30, typed or a free one picked from the chain) for its owner's keys (their key card — role "owner" — or a pp-client .pub file), how many of them sign, what it starts with, and the fee (the metadata fee plus the config's newAccountFee: pp-ledger's `minimumFeeFor` leaves that flat part out, so `apps_net` adds it — to fix upstream). Built and checked in `apps_net` (`makeIssuedAccount`, unit-tested). Checked against a real chain: `scripts/chain_smoke.sh` creates an account for a fresh key, funded by the registrar, and finds it on chain with that key and balance |
| Genesis (ad8) | Done | `pp-ledger-genesis`: the genesis plan — the network, its start (a date and time, or +hours), who holds the admin set, the recovery set, the reserve, registrar, fee and recycle accounts (key cards and vault keys by role, how many sign), the beacon's key (its operator's card), the genesis miners and their stakes, the settings from pp-ledger's defaults (`chain_genesis::defaultConfig`, pp-ledger #146) — made into block 0 by `chain_genesis::records` for the admin set to sign offline; recovery announcements (the recovery set names a new admin set).
